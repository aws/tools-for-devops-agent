# Checks — Model Invocation (LLM-INV)

Covers Amazon Bedrock on-demand invocations, cross-region inference profiles, and model access grants.

Each row: `check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation`

Family code: **INV** = model invocation. Family prefix: `LLM-INV-`.

Severity scale: CRITICAL > HIGH > MEDIUM > LOW > INFO. Thresholds without an AWS-published value are marked `workload-specific` at severity INFO.

| check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation |
|---|---|---|---|---|---|
| LLM-INV-001 | Operational Excellence | CRITICAL | `GetModelInvocationLoggingConfiguration` returns no `loggingConfig`, or `loggingConfig` present but both `cloudWatchConfig` and `s3Config` absent — model invocation logging is disabled. Without it there is no record of prompts, completions, token counts, or errors. | Enable model invocation logging via `PutModelInvocationLoggingConfiguration` with a CloudWatch log group and/or S3 destination. Enable `textDataDeliveryEnabled`, `imageDataDeliveryEnabled`, `embeddingDataDeliveryEnabled` as appropriate. | https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html |
| LLM-INV-002 | Reliability | HIGH | Application invokes a foundation model by direct model ID (e.g. `anthropic.claude-3-5-sonnet-20241022-v2:0`) rather than a cross-region inference profile ID (e.g. `us.anthropic.claude-3-5-sonnet-...`), and a system-defined profile exists for that model (check `ListInferenceProfiles`; if none exists, do not raise). No automatic cross-region failover or capacity spreading on throttling. | Switch high-throughput, latency-tolerant workloads to a cross-region (system-defined) inference profile so Bedrock routes across regions and absorbs regional throttling. | https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html |
| LLM-INV-003 | Operational Excellence | HIGH | A model ID or inference profile in use maps to a model version Bedrock has marked for deprecation / legacy (lifecycle status not `ACTIVE`), per `ListFoundationModels` `modelLifecycle.status`. | Migrate to the current-generation model or the current snapshot of the same family before the end-of-life date; re-run evaluation (see LLM-EVAL) against the new version. | https://docs.aws.amazon.com/bedrock/latest/userguide/model-lifecycle.html |
| LLM-INV-004 | Security/Responsible-AI | HIGH | IAM policy grants `bedrock:InvokeModel` / `bedrock:InvokeModelWithResponseStream` on `Resource: "*"` instead of scoping to specific `foundation-model` / `inference-profile` ARNs. Model access is not least-privilege. | Scope invoke permissions to the exact model and inference-profile ARNs the workload needs; use `bedrock:InvokeModel` resource ARNs and condition keys. | https://docs.aws.amazon.com/bedrock/latest/userguide/security_iam_id-based-policy-examples.html |
| LLM-INV-005 | Reliability | MEDIUM | `GetModelInvocationLoggingConfiguration` shows logging enabled but delivery is failing (CloudWatch `ModelInvocationLogDeliveryFailure`-style gaps, or S3 destination unwritable / bucket policy denies `bedrock.amazonaws.com`). Logs enabled but not landing. | Fix the S3 bucket policy / KMS key policy / CloudWatch log group permissions so the Bedrock service principal can deliver; verify a test invocation appears. | https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html |
| LLM-INV-006 | Performance | MEDIUM | Streaming-capable interactive workload uses `InvokeModel` (buffered) rather than `InvokeModelWithResponseStream`, inflating perceived latency / TimeToFirstToken for end users. | Use `InvokeModelWithResponseStream` (or the Converse streaming API) for user-facing chat so first tokens render early. | https://docs.aws.amazon.com/bedrock/latest/userguide/inference-invoke.html |
| LLM-INV-007 | Reliability | MEDIUM | Sustained capacity rejections over the evaluation window — `InvocationThrottles` > 0 and/or quota rejections (`InvocationClientErrors` with `errorCode` `ServiceQuotaExceededException`), counted from both the per-`ModelId` and the no-dimension `AWS/Bedrock` series — with no retry-with-backoff and no inference-profile spreading; requests are being dropped. | Implement exponential backoff with jitter, adopt a cross-region inference profile, and if sustained request a quota increase or Provisioned Throughput (see LLM-PT). Quota increases are not granted for Legacy or Deprecated models — check lifecycle first and migrate instead. | https://docs.aws.amazon.com/bedrock/latest/userguide/quotas.html |
| LLM-INV-008 | Operational Excellence | MEDIUM | Workload standardizes on per-model native request/response bodies rather than the unified Converse API, increasing maintenance cost and blocking uniform tool-use / system-prompt handling across models. | Migrate to the Converse / ConverseStream API for a model-agnostic request shape and consistent multi-turn + tool-use handling. | https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html |
| LLM-INV-009 | Cost Optimization | MEDIUM | Large, latency-tolerant, high-volume jobs run through on-demand `InvokeModel` instead of Batch inference, paying the higher on-demand rate for work that is not time-sensitive. | Move offline / bulk generation to Bedrock Batch inference (`CreateModelInvocationJob`) for the discounted batch rate. See cost-analysis.md. | https://docs.aws.amazon.com/bedrock/latest/userguide/batch-inference.html |
| LLM-INV-010 | Security/Responsible-AI | HIGH | Invocation logging is enabled with text/image data delivery ON but the destination S3 bucket is not encrypted with a customer-managed KMS key and/or is not access-restricted — prompt and completion content (possibly sensitive) is weakly protected. | Encrypt the logging destination with a CMK, restrict bucket access, and consider disabling raw text/image data delivery if content is sensitive and only metadata is required. | https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html |
| LLM-INV-011 | Performance | LOW | No client-side request-level timeout / token-budget cap configured; runaway generations consume output tokens and latency. `max_tokens` (or `maxTokens` in Converse `inferenceConfig`) not set. | Set `maxTokens` and sensible stop sequences per use case; cap context length. Threshold is `workload-specific`. | https://docs.aws.amazon.com/bedrock/latest/userguide/inference-parameters.html |
| LLM-INV-012 | Operational Excellence | INFO | Prompts are hard-coded in application source rather than managed in Bedrock Prompt Management, so prompt changes are untracked and unversioned. Threshold `workload-specific`. | Store production prompts in Bedrock Prompt Management with versions; reference by version from code (see LLM-AGT-003). | https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management.html |
| LLM-INV-013 | Security/Responsible-AI | HIGH | `iam:SimulatePrincipalPolicy` on the caller's principal for `bedrock:InvokeModel` returns `implicitDeny` or `explicitDeny` — the caller cannot invoke the model they need. For `explicitDeny`, check SCPs via Organizations policy read. An SCP deny overrides all IAM allows. | For implicitDeny: add the missing Allow. For SCP explicitDeny: the deny is in an organizational policy — escalate to the org admin; the customer cannot fix this themselves. Always distinguish SCP deny from IAM deny in the prescription. | https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_testing-policies.html |
| LLM-INV-014 | Reliability | HIGH | Model access not granted — `bedrock:GetFoundationModelAvailability` or the model access page shows the model is not enabled for this account. For marketplace models, the marketplace subscription was never accepted. This is the #2 Bedrock support theme (access denied). | For AWS models: request model access in the Bedrock console (Model access page). For marketplace models: accept the subscription in AWS Marketplace first, then request access. | https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html |
| LLM-INV-015 | Reliability | MEDIUM | SCP explicit deny detected on `bedrock:*` or `bedrock:InvokeModel` actions — the organization blocks Bedrock usage for this account. No IAM change in the account can override this. | Escalate to the AWS Organizations administrator. Provide the specific SCP policy name and the deny statement. Do NOT prescribe an IAM fix — SCP denies cannot be overridden by account-level IAM. | https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html |
