# Changelog

All notable changes to this skill are documented here. New entries go at the top.

## [1.0.0] - 2026-11-18

Initial release for AWS DevOps Agent (chat agent type).

### Added

- Read only CloudTrail coverage audit for one account: trail and CloudTrail Lake event data store inventory across every enabled Region with shadow trails de duplicated by ARN, trail status, event selectors and Insights selectors, and a list only resource inventory of S3 buckets, Lambda functions and DynamoDB tables (`ListBuckets` plus `GetBucketLocation`, `ListFunctions`, `ListTables`; `DescribeTrails` per Region with no `trailNameList`; `GetTrail`, `DescribeTable` and `GetFunction` are never called).
- Five coverage states per resource as an ordered first match list: `NotApplicable`, `Unknown`, `Covered`, `CoveredByOrgTrail-Unverified`, `Uncovered`. A `Covered` row keeps its narrowing in the state cell (`write only`, `read only`, `prefix`, `eventName`, `excludes service-initiated events`), and a narrowed row makes D1 to D3 `PASS (narrowed)` rather than `PASS`.
- Basic and advanced event selector semantics with documentation sources, including the multipart upload and `DeleteObjects` gap in `eventName` allowlists. `eventType` and `userIdentity.arn` exclusions are evaluated on data event selectors for trails (the only selector type on which a trail accepts those fields) and on management selectors for event data stores.
- Organization trail handling from a member account: status and selectors are requested once each with the full trail ARN. The agent's AWS tool blocks the cross account ARN before the request reaches AWS, so the result is `ToolingFailure` (not `AccessDenied`), the affected resources are `CoveredByOrgTrail-Unverified`, the rating caps at `Attention`, and Next Steps carries the full ARN and the `aws cloudtrail get-event-selectors --trail-name <ARN>` command for the operator. An organization trail homed in an opt in Region the member has not enabled is treated as contributing nothing to that member (O2), using `ec2:DescribeRegions AllRegions=true` for the member's `OptInStatus`.
- Fixed 20 check matrix (T1, T2, M1 to M3, D1 to D4, I1, L1 to L4, E1, E2, O1, O2, N1, N2) with severities and a rating roll up `Healthy`, `Attention`, `AtRisk`, `Indeterminate`. The Event history (90 days, management events only) and automated system attribution notes render on every run. A stopped trail or a KMS or RDS source exclusion whose events another trail records is INFO, not a gap; more than one trail recording the same events is a count, never a finding, so the skill does not reverse `cloudtrail-cost-optimization` advice.
- Baseline mode and required list mode; inline data mode for pasted `DescribeTrails`, `GetEventSelectors` or `GetTrailStatus` output labelled `SUPPLIED DATA`, with the account id taken from the supplied ARNs or reported as not supplied, every section rendered, and unassessable rows `Unknown` with the reason.
- Output contract: the final message is the full report (Scope, Coverage Rating with a one line Bottom line, Resource Coverage, Next Steps, Trail Inventory, Findings, Check Matrix, What Auditors Should Know, Not Assessed) and ends at Not Assessed with no closing offer to change configuration, open a support case, draft API calls, re-run elsewhere or extend the report. A chat agent relaying a subagent's report delivers it unchanged (relay rule in SKILL.md; the report carries no note to the parent).
- Scope boundary with `cloudtrail-cost-optimization` and `unified-security-cost-optimizer` (cost, duplicate trail waste and data event charges are a negative trigger here), and with Security Hub control scoring and log content investigation.
- References: coverage model, check matrix, API reference with error classification and quirks, permissions (every action is in `AIDevOpsAgentAccessPolicy` v16, checked 2026-11-18; no additional permissions), report template with pre render validation. README design decisions with documentation sources. 12 evals (6 live account, 4 inline data, 2 negative) graded on substance, each positive eval with one universal safety assertion and assertions that only a correct skill run satisfies.
