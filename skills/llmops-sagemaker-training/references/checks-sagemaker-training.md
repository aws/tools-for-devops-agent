# Checks — SageMaker training / fine-tuning / customization jobs (LLM-SM-TRAIN-*)

Covers Amazon SageMaker training jobs that customize an LLM — Nova fine-tuning/SFT/LoRA recipes and JumpStart fine-tuning.

Each row: `check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation`

Family code: **SM** = SageMaker for LLMs. Family prefix: `LLM-SM-`; the `LLM-SM-TRAIN-*` sub-family covers training / customization.

Severity scale: CRITICAL > HIGH > MEDIUM > LOW > INFO. A *tuning or right-sizing judgment* with no AWS-published number is marked `workload-specific` at severity INFO; a *binary present/absent/failed* state (a job FAILED, no checkpoint produced, access denied) keeps its catalog severity even when AWS publishes no number.

## Training / fine-tuning / customization jobs (LLM-SM-TRAIN-*)

Covers SageMaker training jobs that customize an LLM — Nova fine-tuning/SFT/LoRA recipes and JumpStart fine-tuning. One check per distinct failure mode; a failed, empty, or stalled GPU run is billed, so the cost consequence is noted inside TRAIN-002/007/008 rather than as a separate row.

| check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation |
|---|---|---|---|---|---|
| LLM-SM-TRAIN-001 | Reliability | HIGH | `DescribeTrainingJob` / customization job `TrainingJobStatus` = `Failed` with a `FailureReason` indicating malformed or corrupt training data — Bedrock Converse JSONL that does not parse, a record missing required `messages`/`role`/`content` keys, or the invalid-sample count exceeding the recipe's tolerance. The failure is in the **data**, not capacity. | Validate every JSONL record against the Converse fine-tuning schema offline before resubmitting; fix or drop the malformed records; if the recipe exposes an invalid-sample tolerance, confirm the real drop rate rather than raising the tolerance to mask corrupt data. | https://docs.aws.amazon.com/nova/latest/userguide/fine-tune-prepare-data-understanding.html |
| LLM-SM-TRAIN-002 | Reliability | HIGH | Job `Failed`/stuck with `FailureReason` or secondary status showing `InsufficientInstanceCapacity` for the requested GPU instance type — an **AWS-side** capacity shortfall, not a customer misconfiguration. | Do not change the recipe or request a quota increase. Retry with backoff, try an alternate GPU instance type or a different AZ/region the recipe supports, or schedule off-peak. Classify as service-side (see api-quirks capacity trap). Note the GPU time billed for the failed launch. | https://docs.aws.amazon.com/sagemaker/latest/dg/your-algorithms-training-algo-running-container.html |
| LLM-SM-TRAIN-003 | Cost Optimization | HIGH | Job `Failed` with `ResourceLimitExceeded` / an instance-type service quota of **zero** for the requested training instance — a **customer quota** problem distinct from AWS capacity (TRAIN-002). `service-quotas get-service-quota` returns `Value` 0 for that `sagemaker` training-usage quota. | Request a quota increase for the specific SageMaker training instance type via `aws service-quotas request-service-quota-increase --service-code sagemaker --quota-code <code> --desired-value <n>`; distinguish from InsufficientInstanceCapacity which no quota change fixes. | https://docs.aws.amazon.com/general/latest/gr/sagemaker.html |
| LLM-SM-TRAIN-004 | Operational Excellence | HIGH | Job `Failed` with a `FailureReason` citing recipe or hyperparameter validation — a null/omitted required `HyperParameters` value Nova rejects, an out-of-range value, or a malformed recipe reference. Config error, not data or capacity. | Correct the recipe/hyperparameters against the published Nova customization recipe spec (supply all required values, none null, within documented ranges) and resubmit; validate the recipe locally before launch. | https://docs.aws.amazon.com/nova/latest/userguide/customize-fine-tune.html |
| LLM-SM-TRAIN-005 | Security | HIGH | Job `Failed` with an access error — the training/customization execution role cannot read the training-data or recipe S3 location, or cannot write the output path (`AccessDenied`, assume-role failure, or an `s3:GetObject`/`PutObject` denial in `FailureReason`). | Grant the execution role least-privilege `s3:GetObject` on the input/recipe prefixes and `s3:PutObject` on the output prefix (and KMS decrypt if the data is CMK-encrypted); verify the trust policy allows `sagemaker.amazonaws.com`. Report the role by name/ARN with the account segment masked. | https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-roles.html |
| LLM-SM-TRAIN-006 | Reliability | HIGH | Job `Failed`/produced nothing because an input data channel is empty or points at the wrong S3 URI — `DescribeTrainingJob` `InputDataConfig` references a prefix with no objects, a wrong bucket/prefix, or a `ContentType`/channel name the recipe does not expect. | Correct the channel `S3Uri`, content type, and channel name to match the recipe's expected inputs; confirm the prefix actually contains the training objects before resubmitting. | https://docs.aws.amazon.com/sagemaker/latest/dg/your-algorithms-training-algo-running-container.html |
| LLM-SM-TRAIN-007 | Reliability | MEDIUM | Job is `InProgress` with `SecondaryStatus` `Starting`/`Pending` waiting on GPU capacity for an extended period — this is **NOT** `Failed`. Reporting it as a failure is a false positive (see api-quirks Pending-not-Failed trap). | Report the true status (InProgress/Pending-on-capacity), not a failure. Advise waiting, or if the wait is unacceptable, cancel and retry on an alternate instance type/region. Prescribe no config change for a job that has not failed. Note that GPU time only bills once a Pending job starts. | https://docs.aws.amazon.com/sagemaker/latest/dg/API_DescribeTrainingJob.html |
| LLM-SM-TRAIN-008 | Reliability | HIGH | Job reports `Completed` (or `Stopped`) but no model artifact/checkpoint exists at `ModelArtifacts.S3ModelArtifacts` / the recipe's output path — `s3:HeadObject`/`ListObjectsV2` on the output prefix finds no checkpoint. A "succeeded" job that produced nothing is not usable, and GPU time was billed. | Inspect training/CloudWatch logs for a late-stage failure or an output-path misconfiguration; correct the output `S3OutputPath` and resubmit; do not register or deploy a non-existent artifact. Note the billed GPU cost for the empty run. | https://docs.aws.amazon.com/sagemaker/latest/dg/your-algorithms-training-algo-envvariables.html |
