# Checks — Model Invocation (LLM-INV)

Covers Amazon Bedrock on-demand invocations, cross-region inference profiles, and model access grants.

Each row: `check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation`

Family code: **INV** = model invocation. Family prefix: `LLM-INV-`.

Severity scale: CRITICAL > HIGH > MEDIUM > LOW > INFO. Thresholds without an AWS-published value are marked `workload-specific` at severity INFO.

| check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation |
|---|---|---|---|---|---|
| LLM-INV-001 | Operational Excellence | CRITICAL | `GetModelInvocationLoggingConfiguration` returns no `loggingConfig`, or `loggingConfig` present but both `cloudWatchConfig` and `s3Config` absent — model invocation logging is disabled. Without it there is no record of prompts, completions, token counts, or errors. | Enable model invocation logging via `PutModelInvocationLoggingConfiguration` with a CloudWatch log group and/or S3 destination. Enable `textDataDeliveryEnabled`, `imageDataDeliveryEnabled`, `embeddingDataDeliveryEnabled` as appropriate. | https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html |
| LLM-INV-002 | Reliability | HIGH | Application invokes a foundation model by direct model ID or `foundation-model/` ARN (e.g. `anthropic.claude-3-5-sonnet-20241022-v2:0`) rather than an inference profile ID (e.g. `us.anthropic.claude-3-5-sonnet-...`, `global.anthropic...`), **and** `ListInferenceProfiles` (`typeEquals=SYSTEM_DEFINED`, paged fully) shows a profile whose `models[]` contains that model in the Region. If no such profile exists, do not raise. No automatic cross-region failover or capacity spreading on throttling. | Switch high-throughput, latency-tolerant workloads to the cross-region (system-defined) inference profile so Bedrock routes across regions and absorbs regional throttling; cite the profile id. | https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html |
| LLM-INV-003 | Operational Excellence | HIGH | A model in use (resolve profiles to their member model) has `modelLifecycle.status` `LEGACY` in `ListFoundationModels` / `GetFoundationModel`, or is end-of-life: absent from `ListFoundationModels` and `GetFoundationModel` returns `ResourceNotFoundException` "This model version has reached the end of its life". Invoking an EOL model can surface as `AccessDeniedException`. `AWS/Bedrock` `LegacyModelInvocations` > 0 is a direct signal. Only Bedrock's dates (model card, Model lifecycle page) count; never estimate one. | Migrate to the current-generation model or the current snapshot of the same family before the end-of-life date (for an EOL model: now, via an ACTIVE inference profile); re-run evaluation (see LLM-EVAL) against the new version. No IAM change makes an EOL model invocable. | https://docs.aws.amazon.com/bedrock/latest/userguide/model-lifecycle.html |
| LLM-INV-004 | Security/Responsible-AI | HIGH | IAM policy grants `bedrock:InvokeModel` / `bedrock:InvokeModelWithResponseStream` on `Resource: "*"` instead of scoping to specific `foundation-model` / `inference-profile` ARNs. Model access is not least-privilege. | Scope invoke permissions to the exact model and inference-profile ARNs the workload needs; use `bedrock:InvokeModel` resource ARNs and condition keys. | https://docs.aws.amazon.com/bedrock/latest/userguide/security_iam_id-based-policy-examples.html |
| LLM-INV-005 | Reliability | MEDIUM | `GetModelInvocationLoggingConfiguration` shows logging enabled but delivery is failing: `AWS/Bedrock` `ModelInvocationLogsCloudWatchDeliveryFailure`, `ModelInvocationLogsS3DeliveryFailure`, or `ModelInvocationLargeDataS3DeliveryFailure` > 0 over the window, or `Invocations` > 0 with no recent log events / objects at the destination. No `Invocations` datapoints = nothing to deliver; do not pass or fail on it. | Fix the S3 bucket policy / KMS key policy / CloudWatch logging role so the Bedrock service principal can deliver; verify a test invocation appears. | https://docs.aws.amazon.com/bedrock/latest/userguide/monitoring-runtime-metrics.html |
| LLM-INV-006 | Performance | MEDIUM | Streaming-capable interactive workload uses `InvokeModel` (buffered) rather than `InvokeModelWithResponseStream`, inflating perceived latency / TimeToFirstToken for end users. | Use `InvokeModelWithResponseStream` (or the Converse streaming API) for user-facing chat so first tokens render early. | https://docs.aws.amazon.com/bedrock/latest/userguide/inference-invoke.html |
| LLM-INV-007 | Reliability | MEDIUM | Sustained `InvocationThrottles` (`AWS/Bedrock` Sum > 0 over the evaluation window, queried per `ModelId` **and** with no dimension, because requests that fail before model resolution are published only without `ModelId`) with no retry-with-backoff and no inference-profile spreading. Quota rejections are counted in `InvocationClientErrors`, not `InvocationThrottles`, and metrics cannot split them from other client errors: report that as a gap, do not raise on it. No throttle datapoints says nothing about backoff handling (not evaluable). | Implement exponential backoff with jitter, adopt a cross-region inference profile, and if sustained request a quota increase or Provisioned Throughput (see LLM-PT). Quota increases are not expected to be approved for Legacy models; check lifecycle first. | https://docs.aws.amazon.com/bedrock/latest/userguide/quotas.html |
| LLM-INV-008 | Operational Excellence | MEDIUM | Workload standardizes on per-model native request/response bodies rather than the unified Converse API, increasing maintenance cost and blocking uniform tool-use / system-prompt handling across models. | Migrate to the Converse / ConverseStream API for a model-agnostic request shape and consistent multi-turn + tool-use handling. | https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html |
| LLM-INV-009 | Cost Optimization | MEDIUM | Large, latency-tolerant, high-volume jobs run through on-demand `InvokeModel`/`Converse` instead of Batch inference, confirmed by a signal (volume by caller and hour in invocation logs; no jobs in `ListModelInvocationJobs`). A user's description alone is INFO (unconfirmed). | Move offline / bulk generation to Bedrock Batch inference (`CreateModelInvocationJob`) for the discounted batch rate. Cost modeling is out of scope (see `related-skills.md`). | https://docs.aws.amazon.com/bedrock/latest/userguide/batch-inference.html |
| LLM-INV-010 | Security/Responsible-AI | HIGH | Invocation logging is enabled with text/image data delivery ON and a destination is weakly protected: a CloudWatch Logs log group with no `kmsKeyId` (report `retentionInDays` absent as never-expires in the same evidence), or an S3 bucket / `largeDataDeliveryS3Config` bucket that is not SSE-KMS with a customer-managed key or not access-restricted. Prompt and completion content (possibly sensitive) is weakly protected. | Log group: `aws logs associate-kms-key` (key policy must allow the CloudWatch Logs service principal) and `aws logs put-retention-policy`. S3: SSE-KMS with a CMK, restrict bucket access. Consider disabling raw text/image delivery if only metadata is needed. | https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html |
| LLM-INV-011 | Performance | LOW | No client-side request-level timeout / token-budget cap configured; runaway generations consume output tokens and latency. `max_tokens` (or `maxTokens` in Converse `inferenceConfig`) not set. | Set `maxTokens` and sensible stop sequences per use case; cap context length. Threshold is `workload-specific`. | https://docs.aws.amazon.com/bedrock/latest/userguide/inference-parameters.html |
| LLM-INV-012 | Operational Excellence | INFO | Prompts are hard-coded in application source rather than managed in Bedrock Prompt Management, so prompt changes are untracked and unversioned. Threshold `workload-specific`. | Store production prompts in Bedrock Prompt Management with versions; reference by version from code (see LLM-AGT-003). | https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management.html |
| LLM-INV-013 | Security/Responsible-AI | HIGH | The caller is denied `bedrock:InvokeModel` by an in-account control: the AccessDenied message carries `because no identity-based policy allows` / `with an explicit deny in an identity-based policy` (or a permissions-boundary, session, or VPC endpoint policy clause), or the principal's policies, evaluated statically (`iam:SimulatePrincipalPolicy` is never called), have no Allow or an explicit Deny for the failing ARN. Read the principal's policies and compare the `bedrock:InvokeModel*` Resource list with the failing ARN; disclose what stays unconfirmed. Rule out EOL (LLM-INV-003) first. | Add the missing Allow scoped to the failing model / profile ARNs (a profile also needs the member-Region foundation-model ARNs), or remove the in-account Deny. If the deny is an SCP, see LLM-INV-015 instead. | https://docs.aws.amazon.com/IAM/latest/UserGuide/troubleshoot_access-denied.html |
| LLM-INV-014 | Reliability | HIGH | Model access is not in place for the account: `GetFoundationModelAvailability` `agreementAvailability.status` is `PENDING`, `NOT_AVAILABLE`, or `ERROR`, or the error says `model is not available for this account`. In commercial Regions most serverless models are enabled on first invocation; it fails if the first invoking principal lacks `aws-marketplace:Subscribe` / `Unsubscribe` / `ViewSubscriptions`, the account lacks a payment method, or (Anthropic) the first-time-use form was not submitted. `AVAILABLE` does not rule out an EOL model (LLM-INV-003). | Make the first invocation from a principal with the Marketplace permissions that satisfies any `bedrock:InvokeModel` condition keys; for Anthropic submit the use-case form (`PutUseCaseForModelAccess` or console) first. If prerequisites are met and the model is supported in the Region but AccessDenied persists, contact AWS for additional access. The Model access console page applies to AWS GovCloud (US). | https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html |
| LLM-INV-015 | Reliability | MEDIUM | An SCP denies `bedrock:*` or `bedrock:InvokeModel` for the account: the message says `with an explicit deny in a service control policy` / `because no service control policy allows`, or simulation shows `AllowedByOrganizations: false`, or an Organizations policy read (management or delegated-admin account only) shows the deny. `DescribeOrganization` → `AWSOrganizationsNotInUseException` means not in an Organization: **not applicable**. | Escalate to the AWS Organizations administrator with the denied action, resource, and evidence (policy name and statement when readable). Do NOT prescribe an IAM fix — account-level IAM cannot override an SCP. | https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html |
