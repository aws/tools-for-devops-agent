# Checks — SageMaker inference (LLM-SM-001..011, LLM-SM-SERVE-*, LLM-SM-BATCH-*)

Covers Amazon SageMaker inference serving a GenAI / LLM workload — real-time endpoints (reliability, operational excellence, cost, security, and performance/right-sizing posture), serverless and asynchronous endpoints (cold start, concurrency, async queue/notification wiring, and the fit decision), and batch transform jobs used for offline LLM scoring (failure, right-sizing, output integrity, and encryption).

Each row: `check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation`

Family code: **SM** = SageMaker for LLMs. Family prefix: `LLM-SM-`; the numbered `LLM-SM-001..011` cover real-time inference endpoints, the `LLM-SM-SERVE-*` sub-family covers serverless & asynchronous inference, and the `LLM-SM-BATCH-*` sub-family covers batch transform.

Severity scale: CRITICAL > HIGH > MEDIUM > LOW > INFO. A *tuning or right-sizing judgment* with no AWS-published number is marked `workload-specific` at severity INFO; a *binary present/absent/failed* state (a job FAILED, no checkpoint produced, access denied) keeps its catalog severity even when AWS publishes no number.

## Real-time inference endpoints (LLM-SM-001..011)

Covers Amazon SageMaker real-time inference endpoints — reliability, operational excellence, cost, security, and performance/right-sizing posture.

| check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation |
|---|---|---|---|---|---|
| LLM-SM-001 | Reliability | HIGH | `DescribeEndpoint` production variant has no Application Auto Scaling target registered (`DescribeScalableTargets` empty for the endpoint/variant) — fixed capacity that cannot absorb load spikes or scale in when idle. | Register the variant with Application Auto Scaling and attach a target-tracking policy (e.g., on `SageMakerVariantInvocationsPerInstance`). | https://docs.aws.amazon.com/sagemaker/latest/dg/endpoint-auto-scaling.html |
| LLM-SM-002 | Operational Excellence | HIGH | Endpoint config has `DataCaptureConfig` disabled / absent and no Model Monitor schedule — no capture of inference inputs/outputs, so drift and data-quality monitoring are impossible. | Enable `DataCaptureConfig` on the endpoint config and attach a Model Monitor schedule (data quality / model quality). | https://docs.aws.amazon.com/sagemaker/latest/dg/model-monitor.html |
| LLM-SM-003 | Cost Optimization | HIGH | A production variant reports `CurrentInstanceCount` = 0 (and is not a serverless or scale-to-zero config) — endpoint is `InService` but cannot serve, or is a leftover variant still billed by config. | Investigate: if abandoned, delete the endpoint; if intended scale-to-zero, confirm serverless/async config; otherwise restore desired instance count. | https://docs.aws.amazon.com/sagemaker/latest/dg/realtime-endpoints.html |
| LLM-SM-004 | Operational Excellence | MEDIUM | Only a single production variant exists where safe model rollout matters — no multi-variant setup for A/B testing or canary shifting of traffic between model versions. | Add a second production variant and shift traffic gradually (variant weights) to A/B test or canary new model versions. | https://docs.aws.amazon.com/sagemaker/latest/dg/model-ab-testing.html |
| LLM-SM-005 | Performance | MEDIUM | Instance type/count chosen without running Inference Recommender — likely oversized (cost) or undersized (latency) relative to the model's measured profile. | Run an Inference Recommender job to right-size instance type/count against latency and throughput targets. Threshold `workload-specific`. | https://docs.aws.amazon.com/sagemaker/latest/dg/inference-recommender.html |
| LLM-SM-006 | Security | HIGH | Endpoint config / model has no `VpcConfig` where the workload requires private networking — inference traffic and model artifacts are not confined to the VPC. | Configure `VpcConfig` (subnets + security groups) on the model so the endpoint runs inside the VPC; use VPC endpoints for AWS API access. | https://docs.aws.amazon.com/sagemaker/latest/dg/host-vpc.html |
| LLM-SM-007 | Security | HIGH | Endpoint config `KmsKeyId` absent — the ML storage volume attached to inference instances is not encrypted with a customer-managed key. | Set `KmsKeyId` on the endpoint config (CMK) to encrypt the inference instance storage volume. | https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_CreateEndpointConfig.html |
| LLM-SM-008 | Cost Optimization | MEDIUM | Low, bursty, or latency-tolerant traffic served by an always-on real-time endpoint instead of Serverless Inference or Asynchronous Inference — paying for idle instances. Endpoint-side idle-cost signal only; the serverless/async fit decision is LLM-SM-SERVE-005 in this skill's serverless/async area. | Move spiky low-volume traffic to Serverless Inference, and large-payload/long-running inference to Asynchronous Inference. Threshold `workload-specific`. | https://docs.aws.amazon.com/sagemaker/latest/dg/serverless-endpoints.html |
| LLM-SM-009 | Reliability | MEDIUM | Sustained `ModelLatency`/`OverheadLatency` growth or `Invocation5XXErrors` > 0 over the window with no alarm — endpoint degradation is undetected (see cloudwatch-alarm-reference.md). | Add CloudWatch alarms on `ModelLatency` and `Invocation5XXErrors`; investigate container/model-server health. | https://docs.aws.amazon.com/sagemaker/latest/dg/monitoring-cloudwatch.html |
| LLM-SM-010 | Performance | LOW | GPU-backed LLM endpoint shows low `GPUUtilization`/`GPUMemoryUtilization` sustained — over-provisioned GPU, or model would fit a smaller/cheaper accelerator. Threshold `workload-specific`. | Right-size to a smaller GPU instance or consolidate via multi-model/multi-container endpoints; re-validate latency. | https://docs.aws.amazon.com/sagemaker/latest/dg/monitoring-cloudwatch.html |
| LLM-SM-011 | Operational Excellence | LOW | Endpoint not deployed via a tracked model package / registry version — the running model artifact has no lineage to a registered, approved version. Threshold `workload-specific`. | Register models in the SageMaker Model Registry and deploy approved package versions for traceability. | https://docs.aws.amazon.com/sagemaker/latest/dg/model-registry.html |

## Serverless & asynchronous inference (LLM-SM-SERVE-*)

Covers the serverless/async-specific posture the always-on real-time checks (LLM-SM-001..011) cannot — cold start, concurrency, async queue/notification wiring, and the fit decision.

| check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation |
|---|---|---|---|---|---|
| LLM-SM-SERVE-001 | Performance | MEDIUM | Serverless endpoint shows elevated `ModelSetupTime` (cold-start) in `AWS/SageMaker` with no Provisioned Concurrency configured on the `ServerlessConfig` — first-call latency spikes under bursty traffic. Threshold `workload-specific`. | Set Provisioned Concurrency on the serverless variant sized to the concurrent-request floor, or move latency-critical paths to a real-time endpoint; re-measure `ModelSetupTime`. | https://docs.aws.amazon.com/sagemaker/latest/dg/serverless-endpoints.html |
| LLM-SM-SERVE-002 | Reliability | MEDIUM | Serverless `ServerlessConfig.MaxConcurrency` set at/near the account or config ceiling while invocations are being throttled — concurrency headroom exhausted. Threshold `workload-specific`. | Raise `MaxConcurrency` (within account limits) or add Provisioned Concurrency; if the ceiling is an account quota, request an increase. Confirm throttles are sustained, not a blip. | https://docs.aws.amazon.com/sagemaker/latest/dg/serverless-endpoints.html |
| LLM-SM-SERVE-003 | Reliability | HIGH | Asynchronous endpoint has `AsyncInferenceConfig` present but **no** `OutputConfig.NotificationConfig` (SNS success/error topics) — callers have no completion signal and failures are silent. | Configure `NotificationConfig` with `SuccessTopic` and `ErrorTopic` so completion and failure are observable; verify the endpoint role can publish to the topics. | https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference.html |
| LLM-SM-SERVE-004 | Reliability | MEDIUM | Async endpoint has no scale-to-zero / scaling on the `ApproximateBacklogSizePerInstance` metric — the queue backs up with no instances or pays for idle instances between bursts. Threshold `workload-specific`. | Register Application Auto Scaling on `ApproximateBacklogSizePerInstance` (scale-to-zero supported for async) so instances track queue depth. | https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference-autoscale.html |
| LLM-SM-SERVE-005 | Cost Optimization | MEDIUM | Large-payload or long-running LLM inference served on an always-on real-time endpoint where Async (large/long jobs) or Serverless (spiky low-volume) fits better — paying for idle provisioned instances. Owns the serverless/async fit decision, driven by payload size and invocation duration; the real-time idle-cost signal stays LLM-SM-008 in this skill's real-time area. Threshold `workload-specific`. | Move large-payload/long-running inference to Asynchronous Inference and spiky low-volume traffic to Serverless; re-validate latency and cost. Complements LLM-SM-008 from the real-time side. | https://docs.aws.amazon.com/sagemaker/latest/dg/model-deploy-feature-matrix.html |

## Batch transform / offline scoring (LLM-SM-BATCH-*)

Batch Transform is the offline-scoring path for LLMs (bulk classification, offline generation). Covers failure, right-sizing, output integrity, and encryption.

| check-id | pillar | severity | detection-rule | remediation | AWS-doc-citation |
|---|---|---|---|---|---|
| LLM-SM-BATCH-001 | Reliability | HIGH | `DescribeTransformJob` `TransformJobStatus` = `Failed` — read `FailureReason` for input-data format mismatch, a `ContentType`/`SplitType` the container rejects, or an S3 access error on the input/output path. | Fix the indicated cause (correct `ContentType`/`SplitType`/`BatchStrategy`, or grant the role S3 access to input/output prefixes) and resubmit; validate a small sample first. | https://docs.aws.amazon.com/sagemaker/latest/dg/batch-transform.html |
| LLM-SM-BATCH-002 | Performance | LOW | Batch job runs with `MaxConcurrentTransforms` = 1 / default and no `MaxPayloadInMB` tuning on a large dataset — under-parallelized, long wall-clock and higher cost. Threshold `workload-specific`. | Raise `MaxConcurrentTransforms` and tune `MaxPayloadInMB`/`BatchStrategy` to the record size so instances are saturated; re-measure throughput. | https://docs.aws.amazon.com/sagemaker/latest/dg/batch-transform.html |
| LLM-SM-BATCH-003 | Operational Excellence | MEDIUM | Job reports `Completed` but the output S3 prefix is empty or has fewer `.out` objects than input **files** (`ListObjectsV2` on both prefixes). Batch transform writes one `<input>.out` per input file, and only when every record in that file succeeded, so a missing `.out` names the input file with failed records — partial/failed scoring masked by a success status. Never compare the `.out` count with a record count. | Inspect the transform logs for skipped/failed records, reconcile output count against input, and reprocess the missing records; do not consume a partial output set as complete. | https://docs.aws.amazon.com/sagemaker/latest/dg/batch-transform.html |
| LLM-SM-BATCH-004 | Security | MEDIUM | Transform output written without a `TransformOutput.KmsKeyId` where the scored data is sensitive — offline LLM outputs land in S3 without a customer-managed key. | Set `TransformOutput.KmsKeyId` to a CMK and confirm the output bucket enforces encryption; grant the role KMS encrypt. | https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_TransformOutput.html |
